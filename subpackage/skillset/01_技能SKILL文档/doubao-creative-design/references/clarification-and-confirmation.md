# 澄清与生成确认协议

本 reference 是 `doubao-creative-design` 唯一的用户澄清与生成确认规则来源。任何补信息、让用户选择、确认生成、确认继续批次或确认方向的行为都必须遵守本文件；其他文件不得另设提问轮次或问题模板。事实、素材、产物结构、数量、规格，以及会改变素材需求、事实证据、产物路由、生成路径或交付结构的媒介与内容载体等非视觉决策使用 `interaction.ask`；纯审美层面的风格、构图、配色、材质、光线和氛围通过 2–4 张实际试稿澄清，展示后只用普通文本收集视觉锚点选择。

## 适用范围与总原则

本策略只用于图片创作、图片编辑、图生图、抠图、修复和图片批量处理。若请求同时包含视频，且视频部分会改变 Skill 路由或图片交付结构，先澄清最终产物；视频执行规则交给对应视频 Skill，不在本文件扩展。

默认先在内部规划并完整盘点信息缺口，再用一次集中澄清尽可能收集当前阶段所需信息。缺失信息会影响执行路径、Skill 路由、核心资产引用、交付范围、内容可用性、事实准确性，或会导致错误产物、事实编造、无效生成和明显返工时，触发澄清。

核心原则：

1. 优先澄清阻塞当前执行的信息，并同时覆盖会显著影响成品可用性、信息完整度或返工成本的高价值缺口；不询问与执行无关的偏好。
2. 已明确的信息不重复确认；可安全默认的非事实信息由 Agent 决定，并写入内部计划。
3. 先锁定最终产物，再讨论视觉方向；产物未定时不提案、不排版、不生成。
4. 普通澄清与生成确认不得连续叠加；同一执行阶段只要用户已经回答普通澄清，就直接按答案执行，不再追加生成确认。
5. 人物、品牌、产品、日期、价格、卖点、联系方式、规则、版权素材等事实不得擅自编造。
6. 用户明确说“你自己定”“随便定”时，视为授权 Agent 对非事实视觉项采用安全默认值；不等于授权编造事实、数量或身份特征。

## 强制工具门禁

非视觉决策一旦需要用户回答、选择或确认，必须调用 `interaction.ask`。这包括核心事实、素材角色、产物类型、内容结构、数量规格、生成确认、是否继续下一批等场景。纯视觉方向不得调用 `interaction.ask`；需要用户判断时，执行“视觉试稿澄清与风格改稿”。

任何图片工具调用前都必须在内部完成 `clarification_gate_passed` 判定：当前产物路由已经锁定；所有会改变事实准确性、素材需求、执行路径、内容结构、数量规格或交付范围的非视觉问题均已明确；需要澄清时已调用 `interaction.ask` 并合并回答。未完成该判定时，不得以产物 ref 的默认值、内部推断、核心资产先生成或视觉试稿为理由开始生图。

- 非视觉问题不得用普通文本、Markdown 列表、自然语言选项、结尾问句或其他工具代替；展示 2–4 张视觉试稿后的锚点选择必须使用普通文本，不调用澄清工具。
- 不得先用普通文本提问，再补 `interaction.ask`。
- 不得在调用前后重复同一问题。
- 问题数量不设内部目标值，严格服从宿主单次 1–4 个问题的协议上限。先盘点全部已知缺口，再使用完成当前阶段所需的问题数量；有多个高价值缺口时尽量用满可用问题位，只有一个有效问题时只问一个。
- 同一执行阶段默认只允许进行一次普通澄清。首次调用必须合并所有当前可预见的阻塞项，避免用户回答后又逐项追问。
- 用户回答后立即把返回值写入执行参数并继续，不得为了“再确认一次”重复调用 `interaction.ask`；继续时先返回主 `SKILL.md` 的串行流程读取模型改写策略。
- `interaction.ask` 不可用或调用失败时，不得降级为普通文本澄清；停止所有依赖该答案的生成步骤，仅陈述工具失败与被阻塞的执行阶段。

## 决策顺序

严格按以下顺序判断：

1. 用户是否只要方案、提示词或建议？
   - 是：直接交付文本，不调用生成工具，也不做生成确认。
   - 否：继续。
2. 最终产物类型是否明确？
   - 否：用 `interaction.ask` 锁定产物类型和内容结构。
   - 是：继续。
3. 是否缺少不可替代的事实、edit target、产品或人物参考、品牌素材、数据来源或必须保持的身份特征？
   - 是：用 `interaction.ask` 只询问缺失项。
   - 否：继续。
4. 数量、版本差异、尺寸、比例或分辨率是否会改变工作量或产物结构且尚未明确？
   - 是：用 `interaction.ask` 澄清。
   - 否且满足安全默认条件：采用默认值并写入内部计划。
5. 是否存在会显著改变风格、构图、配色、材质、氛围或纯审美表现的互斥方向？
   - 是，且事实、核心资产、内容形态、所需素材、产物路由和交付规格已经锁定：不调用 `interaction.ask`，直接生成 2–4 张同内容试稿，再用普通文本收集视觉锚点选择。
   - 是，但仍有非视觉硬阻塞：先用一次 `interaction.ask` 合并解决非视觉问题；用户回答后先读取模型改写策略，再直接生成视觉试稿，不再调用确认工具。
   - 否：采用最符合内容密度和行业证据的视觉方案继续。
   - 若“实景 / 插画 / 3D / 纯文字排版”等选择会改变素材需求、事实证据、生成路径、产物类型或交付结构，则它不是本步的纯视觉方向，必须回到非视觉澄清并调用 `interaction.ask`。
6. 是否达到生成确认门槛？
   - 当前阶段已经调用过普通澄清且用户已回答：跳过生成确认，先读取模型改写策略再执行。
   - 当前阶段正在执行视觉试稿澄清：直接生成试稿，不做生成确认；用户选定锚点后直接继续，不追加确认。
   - 当前阶段未调用过普通澄清，且未达到确认门槛：直接执行。
   - 当前阶段未调用过普通澄清，但达到确认门槛：先用普通文本展示最终参数，再单独调用一次 `interaction.ask` 确认是否生成。

## 必须澄清的阻塞项

出现任一项即使用 `interaction.ask`：

- 指代对象、用户参考图、历史生成图、edit target 或核心资产不清。
- 用户参考图和历史生成图同时存在，且不同参考来源会改变最终结果。
- 缺少不可替代的事实：人物身份、活动时间或地点、品牌或产品准确名称、价格、核心卖点、联系方式、规则、版权图片、Logo、销量、折扣、功效、认证、数据或监管声明。
- 必需的上传图片、产品原图、人物参考、品牌资产或数据文件缺失。
- 横版与竖版、单图与分层、交付格式等非视觉规格互相冲突。
- 用户说“一套”“几张”“多个版本”“批量”“系列”，但没有明确数量或逐项差异。
- “几个版本”未说明版本数量以及每个版本改变什么。
- 非视觉决策没有安全默认值，任一选择都会明显改变核心结果。
- 垂类任务缺失 2 项及以上关键参数，且无法从上下文可靠推断。
- 达到生成确认门槛，且当前执行阶段此前没有进行过普通澄清。

主观审美词存在多个互斥落地方式时，不属于 `interaction.ask` 阻塞项；在非视觉信息充分后进入视觉试稿澄清。

### 多图缺失规则的优先级

套图、系列图、叙事多图、绘本、故事分镜、连续页、H5 长页、电商套图等涉及叙事逻辑、页面顺序、卖点递进、角色连续性或内容分镜的输出，按以下优先级处理：

1. 数量不明、逐项差异不明、核心资产不明、事实缺来源或要求冲突属于硬阻塞，无论缺失项总数多少都必须澄清。
2. 硬阻塞均已排除后，若只缺失 1 项可安全默认的垂类参数，内部补全并继续。
3. 若缺失 2 项及以上垂类关键参数，必须先澄清，不得仅凭按钮或短指令生成整套。

这套优先级覆盖其他产物 reference 中的默认张数建议；默认张数不能绕过“一套、系列、批量、多个版本”的数量与差异门禁。

## 垂类关键参数与缺失计数

- 品牌：品牌 / 行业 / 客群；定位 / 核心价值；必须沿用的已有资产；交付范围。
- 电商：品牌 / 品类；核心卖点 / 人群 / 购买理由；产品原图与必须保持项；用途范围 / 目标平台 / 张数。
- IP：品牌 / 品类；角色理念 / 性格 / 世界观；必须保持的角色资产；用途范围。
- 信息图：主题；用途 / 场景；受众；核心内容与数据来源。
- 社媒：平台；内容目标；受众；传播语气；产物类型。
- 叙事多图 / 绘本 / 分镜：主题 / 故事梗概；主角设定；受众 / 年龄段；页数 / 张数。

同一组斜杠项按一个决策维度计数。可以由明确上下文可靠推断的项不计为缺失；事实、身份和硬阻塞不得通过推断消除。纯审美层面的风格、构图、配色、材质、光线和氛围不计入垂类缺失项，不得仅因缺少这些信息调用 `interaction.ask`。媒介、内容载体或表现形式如果会改变素材需求、事实证据、产物路由、生成路径或交付结构，必须作为非视觉决策计入并澄清。

## 默认值边界

只有同时满足以下条件才能默认：

- 不是事实信息或身份特征。
- 默认后仍可交付可用结果。
- 有稳定行业惯例或上下文依据。
- 不违背用户已表达的偏好。
- 不显著增加生成成本。

不得默认：

- 人名、品牌名、产品型号、日期、地点、价格、规则、卖点、联系方式和 Logo。
- “一套”“批量”“多个版本”的数量与逐项差异。
- 达到生成确认门槛的数量、规格与素材范围。
- 人物或产品必须保持的身份特征。
- 没有上下文依据的互斥视觉方向不得静默默认；需要用户判断时生成 2–4 张视觉试稿。

单张普通图片在主题、用途、主体与视觉要求充分时，不为比例、轻微光线、装饰或常规留白提问。图片编辑必须锁定 edit target、必须保持的内容和允许改变的内容；缺少任一不可替代项时澄清。

## 澄清方法

### 模糊创意方向

把抽象形容词转译成 2–4 个互斥、可执行的视觉试稿 prompt，并直接生成实际图片，不调用 `interaction.ask` 展示文字选项。每个试稿至少明确以下三项：

- 媒介：商业摄影、拼贴、手绘、3D、平面图形、纪实或编辑设计。
- 构图：主体占比、视角、留白、对称或偏轴、密度和阅读动线。
- 色彩与光线：高或低明度、冷暖、硬或柔光、对比度。
- 材质：纸张、金属、玻璃、织物、颗粒、木材、水彩或实体场景。
- 版式：字体气质、文字区位置、图文叠压和标题空间。

不得把“高级一点”“更有氛围”“更有设计感”等抽象词原样写入试稿 prompt，也不得把产物 reference 中的“高级艺术风格”“美学风格扩展”或通用关键词库直接复制成试稿方向。

### 缺少核心信息

只问不补充就会导致编造、空白或不可用的事实：

- 活动海报：活动名、日期、地点、主办方、报名方式。
- 产品宣传：产品准确名称、核心卖点、价格是否展示、产品原图或 Logo。
- 人像：身份特征、是否保持本人、服装或场景限制。
- 信息图 / 教程：准确文案、数据来源、步骤与顺序。
- 图生图 / 产品图：哪张是 edit target、必须保持什么、允许改变什么。

### 数量与规格不明确

选项同时写明数量、内容结构和成本影响，例如：

- 1 张封面：只生成主视觉，成本最低。
- 4 张基础套图：1 张主视觉 + 3 张场景或细节图。
- 6 张完整系列：覆盖主视觉、场景、细节和不同构图，生成成本更高。

不得只问“要几张”；必须同时锁定逐项差异。

## 图片内容形态澄清

`interaction.ask` 不得询问风格。只要画面由什么内容构成尚未明确，就先把“内容形态”作为非视觉结构问题询问；内容形态锁定后，若仍需判断整体视觉方向，再生成实际试稿。优先使用以下四类互斥选项，并结合具体任务改写描述：

- **文字主导**：大标题或核心文案承担第一视觉，搭配色块、线条、符号和少量装饰；适合公告、大字报、金句和信息强调。
- **文字 + 插画**：文字负责信息层级，原创插画负责主体、场景或解释；适合活动、教程、科普、品牌故事和轻叙事内容。
- **图片 + 少量文字**：人物、产品或真实场景照片承担第一视觉，仅保留标题、标签或必要说明；适合产品展示、穿搭、美妆、探店和人物内容。
- **纯画面**：不渲染文字，用主体、场景、动作、光影和色彩表达；适合氛围图、壁纸、概念视觉和后续排版底图。

根据任务需要，再选择一个“内容组织”问题：

- **单主体聚焦**：一个人物、产品或核心物件占据主要画面，信息最集中。
- **主体 + 场景叙事**：主体与环境、动作和道具共同讲清使用场景或事件。
- **多元素信息编排**：多个卖点、步骤、数据或物件进入分区、卡片或标注系统。
- **连续分镜 / 分页**：按时间、步骤或故事顺序拆成多格或多张，强调前后逻辑。

内容形态问题遵守以下规则：

1. 用户已经明确“无字、只要插画、产品照片配标题、纯文字海报”等要求时，不重复询问。
2. 内容形态会影响生成路径、主体素材、文字密度或布局时，视为高优先级问题。
3. 普通澄清只补充尚未明确且会真实改变结果的内容形态、内容组织、核心事实或规格问题；不得为了达到问题数量而询问无关偏好。
4. `display_message` 说明内容形态会影响主视觉、信息密度和后续生成方式，不使用“为了更好地了解需求”等空话。
5. 用户回答内容形态后不再用另一轮问题确认文字比例、插画比例或版式细节；返回主流程读取模型改写策略后直接执行。

## 视觉方向推荐策略

### 限制固定风格参考

除下方“有限整套风格参考”外，不得维护、引用或复述其他固定风格库，也不得把年代、流派、艺术运动、平台热词、艺术家姓名或笼统行业印象作为候选方向。视觉试稿仍须根据当前任务的内容、信息密度、受众、素材真实性和交付场景动态生成。

除明确批准的“全 3D 黏土风”和“全水彩插画风”外，禁止使用“某某风”“某某主义”“某年代美学”作为 Agent 主动设计的试稿标签；尤其不得主动推荐“复古风”“Y2K”“科技风”“未来感”“赛博感”等只表达气氛、不能约束内容组织的名称。用户主动指定此类方向时，可以忠实执行，但必须在内部转译为可见的构图、色彩、光线、材质和版式要求，不扩展为更多同类风格词。

视觉方向不是默认必问题。按以下优先级处理：

1. 用户已明确画风、提供风格参考图、要求延续既有核心资产或品牌系统时，直接继承，不再询问风格。
2. 用户已明确内容类型，且可以从信息密度、素材类型和使用场景推出可靠视觉解法时，单张普通图直接采用该解法；把具体视觉参数写入内部计划，不为收集偏好而提问。
3. 只有存在 2–4 个互斥方向，且不同方向会显著改变媒介、构图、色彩、材质或版式时，才生成视觉试稿；不得先用 `interaction.ask` 罗列文字风格选项。
4. 系列图、批量图或多版本任务需要锁定统一视觉系统时，先从一张代表图生成 2–4 个视觉试稿；用户用普通文本选定锚点后，再延展整套。

优先级固定为：用户明确要求或参考图 > 已锁定品牌 / 核心资产 > 当前内容与信息密度 > 行业可信度与使用场景。产物 reference 中的任何风格词库都不得直接成为试稿方向来源。

### 动态组装视觉方案

每个试稿方向必须是一套能直接生成的视觉解决方案，不能只有风格名。动态组合以下维度：

- **内容载体**：文字、真实图片、产品图、原创插画、图表、流程或空间场景分别承担什么角色。
- **版式结构**：单一主视觉、分区图文、主图配信息卡、步骤轴、对比栏、标注图或连续分页。
- **信息层级**：第一眼看到什么，第二层读取什么，数据、卖点、说明和行动入口如何排序。
- **色彩预算**：背景基色、品牌主色、强调色各自用途，以及允许使用的功能色数量。
- **图像处理**：视角、景别、光线、真实度、材质和是否需要局部放大、剖面或标注。
- **插画处理**：线条粗细、形体概括程度、明暗层级、色块数量和叙事功能；不把插画类型写成固定风格名。

试稿内部标签优先使用能预判内容结构的短名称，例如“主图配信息卡”“流程与数据解释”“真实场景证据”“分区图文说明”，不得使用“方向 A”或“高级风”。“有限整套风格参考”中的三个批准名称可以保留，但每个 prompt 仍须写清内容载体、版式结构、色彩预算和阅读顺序；2–4 张试稿必须在视觉骨架上真正互斥。

### 信息密度适配

先判断内容密度，再决定可推荐的视觉方向：

- **低密度**：一个主题、一个主体和少量文案。允许更大的主体和较多留白，但不默认使用极端留白、微小主体或只有装饰没有信息支点的方案。
- **中密度**：标题加 2–4 个信息点、卖点或步骤。优先使用清楚分区、主次字号、一个主视觉与辅助信息块；通常控制在中性色基底、一个主色和一个强调色。
- **高密度**：5 个及以上信息点，或包含多段正文、数据、步骤、参数、对比、多人 / 多产品、多章节。优先使用模块网格、编号、卡片、分栏、表格、流程箭头、局部标注和分页，先保证扫描顺序与信息容纳能力。

高密度内容的推荐必须遵守：

1. 减少推荐极简、超大留白、单一小主体或过度依赖氛围的方案；这些解法容易压缩有效内容区或造成层级不足。
2. 减少推荐高饱和多色、彩虹渐变、大面积撞色和每个模块各用一种颜色的方案；颜色只承担分组、状态和重点提示，不代替版式层级。
3. 默认色彩预算为中性基底 + 1 个主色 + 1 个强调色；只有数据分类确有需要时增加功能色，并保持同一语义同一颜色。
4. 优先用字号、字重、间距、分隔线、容器、编号和对齐建立层级；不要靠堆叠装饰、纹理或发光效果制造“丰富感”。
5. 不把所有高密度内容做成仪表盘。教程用步骤和局部示意，报告用章节和数据证据，电商用卖点递进，活动信息用时间地点与行动入口优先。

### 科技行业的高质量推荐

科技行业不等于“科技风”。不得主动用蓝紫霓虹、发光电路、悬浮 HUD、全息地球、二进制雨、宇宙背景、无依据的玻璃面板或粒子光线作为默认视觉方向。先判断技术内容属于哪一类，再给能够提升可信度和产品理解的视觉方案：

- **硬件与消费电子**：用真实产品或结构准确的产品图承担第一视觉，结合材质特写、局部放大、尺寸 / 部件标注、爆炸关系或使用场景；色彩服从产品和品牌，不用装饰性电路线抢主体。
- **软件、AI 与 SaaS**：以真实界面、核心工作流、输入输出关系、使用前后对比或代表性结果为证据；没有界面素材时用清楚流程和概念图解释，不虚构可被误认为真实产品的 UI。
- **芯片、云、基础设施与企业技术**：优先架构层级、数据路径、性能尺度、工程细节、设备或机房真实场景；用精确网格和有限强调色表达秩序，不用泛化的“未来城市”替代技术事实。
- **科研、医疗与生命技术**：优先可核验的数据图、结构示意、实验过程、微观图像或真实应用场景；保持来源准确、标注清楚和色彩克制，不用视觉奇观掩盖证据。

科技类候选方案应使用“产品结构展示”“流程与数据解释”“真实应用证据”“工程细节说明”等结果导向标签。高质感来自准确层级、可信素材、真实材质、克制用色、精确光线和有依据的图表 / 标注，而不是来自“科技感”装饰。

### 其他内容与行业适配

- **金融、法律、医疗与企业服务**：优先事实、数据、人物或场景证据，使用稳定网格和克制色彩；避免用华丽装饰削弱可信度。
- **电商与消费品**：优先产品主体、使用场景、细节证据和卖点递进；颜色围绕包装和品牌建立，不让背景颜色数量超过商品本身的信息层级。
- **教育、教程与知识内容**：优先步骤、编号、示意、标注和例子；插画服务解释，不以大面积装饰挤占教学信息。
- **活动与品牌传播**：先建立一个明确视觉焦点，再组织活动名、时间地点、利益点和行动入口；高能量不等于多色、多字体和满版元素。
- **生活方式、文化与亲子内容**：依据受众和素材选择真实图像或原创插画；亲和不等于幼稚，文化表达不等于堆叠传统符号。

### 有限整套风格参考

以下三类可作为视觉试稿候选或用户明确选择后的整套视觉锚点。它们是有限建议，不是每次必须凑齐的固定菜单；仅在内容、受众和交付目标匹配时使用，并通过实际试稿而非 `interaction.ask` 文字选项让用户判断。

- **全 3D 黏土风**：整套主体、人物、道具与环境都采用圆润立体造型、软糖般柔软或半透明质感、清楚体积光和统一材质比例，视觉冲击力最强。适合活动传播、消费品牌、IP、轻科普和需要快速吸睛的内容；不适合必须保持真实产品外观、严肃数据证据或超高文字密度的任务。
- **全水彩插画风**：整套统一为手绘水彩表现，保留纸张肌理、自然晕染、柔和边缘和受控配色，整体治愈温馨。适合生活方式、亲子、节气、旅行、故事与情绪表达；信息较多时只让水彩承担主插图和分区辅助，文字仍需保持清楚层级与足够对比。
- **全实景 + 大字排版**：整套使用真实人物、产品或场景图像承担第一视觉，以大标题、醒目数字、短标签和明确分区组织信息，偏资讯号 / 干货号表达。适合教程、经验总结、测评、探店、知识分享和高信息密度内容；保持照片真实性、文字可读性和统一标题系统，避免多字体、多色块与无关装饰。

整套使用规则：

1. “全”表示系列内的媒介、材质、光线、色彩逻辑和标题系统必须连续一致，不得某页黏土、某页水彩、某页实景混用。
2. 生成 2–4 张视觉试稿时，可以选择其中一个或多个适配方向与其他动态视觉方案对比，但不得为了凑数量强行加入不适合当前内容的方向。
3. 用户从试稿中选中后，将该试稿记录为 `visual-anchor`，后续页面通过 `image_edit` 延展同一材质、角色比例、配色、光线和排版骨架。
4. 高信息密度任务优先评估“全实景 + 大字排版”；若使用 3D 黏土或水彩，必须通过卡片、编号、分区和克制配色保证信息承载，不让画面质感挤占内容。
5. 真实产品、人物身份、Logo 和事实证据需要保持时，不得为了套用全 3D 黏土或全水彩而改造核心资产；此时优先使用全实景方案，或只让插画 / 3D 作为辅助背景与解释元素。

### 视觉试稿方向生成规则

1. 只在视觉方向确实需要用户判断时生成 2–4 张试稿；否则采用最符合内容密度和行业证据的方案直接执行。
2. 试稿方向必须从当前内容现场生成；除“有限整套风格参考”外，不保存通用候选清单，也不从其他 reference 复制风格名。
3. 每个试稿 prompt 说明第一视觉、内容如何分区、图片或插画承担什么功能、色彩预算以及最适合解决的问题。
4. 标签优先以产物结构或证据形式命名，不含年代、流派、艺术家或行业套话；只有使用本文件明确批准的“全 3D 黏土风”“全水彩插画风”时可保留该名称。
5. 需要真实人物、产品、界面、场景或数据作为证据时，不用插画或装饰图形替代真实性。
6. 需要解释步骤、结构或关系时，让图像、插画和标注承担明确解释任务，不推荐只提供氛围的方案。
7. 用户没有明确视觉方向时，根据已确认的内容形态自动选择载体和结构，不再用固定插画 / 摄影风格作为默认值。

### 视觉方向质量检查

生成视觉试稿前逐项检查：

1. 是否本来可以从用户要求、参考图、内容密度或行业证据安全推断；若可以，取消视觉试稿并直接执行。
2. 每个试稿方向是否明确了内容载体、版式结构、信息层级、色彩预算和阅读顺序，而非只列风格名词。
3. 高密度内容是否避免极端留白和过多高饱和颜色，并提供足够的分区、编号、标注或分页能力。
4. 科技类内容是否展示真实产品、界面、流程、数据、工程细节或应用证据，而非套用装饰性“科技感”。
5. 试稿之间是否真正互斥、都适合当前内容，并且没有抽象词、艺术家姓名、年代 / 流派词或平台热词。
6. 用户选中后，该试稿是否能直接成为 `visual-anchor` 延展；若不能，重写 prompt。

## 视觉试稿澄清与风格改稿

### 触发条件

出现以下任一情况时进入本流程：

- 初次生成前，事实、内容、核心素材和规格均已明确，但有 2–4 个互斥视觉方向需要用户判断。
- 用户主动要求“先看看几个方向”“出几种视觉方案”“生成几个风格对比”。

- “不好看”“不喜欢”“太普通”“没感觉”“不够高级”等笼统负向审美反馈。
- “换个风格”“风格不对”“再试几种”“整体重做”等未给出明确替代方向的改稿要求。
- 对当前系列的视觉方向不满意，但没有指出具体构图、配色、材质或版式问题。

本流程只解决视觉方向，不覆盖事实、身份、核心资产、数量或规格硬阻塞。若这些非视觉信息无法确定，先按普通澄清规则调用一次 `interaction.ask`；用户回答后先按主流程读取模型改写策略，再进入本流程，不追加视觉问题或生成确认。

### 不先追问，先做视觉试稿

命中本流程后，不调用 `interaction.ask` 询问纯审美层面的风格、构图、配色、材质、光线、氛围或“哪里不好看”。直接用图像结果帮助用户判断；但若用户提出的媒介变化会改变素材需求、事实证据、产物路由或交付结构，仍须先完成非视觉澄清门禁：

1. 选择一张基准内容。已有图片时优先级为：用户明确指向的图片 > 当前已锁定核心资产 > 最新一批的主图 / 第 1 张 > 最近生成且主体最匹配的图片。全新任务没有基准图时，固定同一主题、文案、主体、比例和素材范围，分别生成试稿。
2. 当用户是对最新一批整体表达审美不满、没有指定某一张时，直接选择最新一批的主图或第 1 张，不因 edit target 再次提问。
3. 默认生成 3 张风格试稿；用户明确要求数量时，在 2–4 张范围内按其要求。每张都从同一张基准图独立生成，不把前一个试稿串联为后一个试稿的参考。
4. 使用 `image_edit` 引用同一基准图，锁定主体身份、产品结构、Logo、核心文字和不可变内容；明确允许重构构图、色彩、光线、材质、装饰与版式。若任务本来没有可引用图片，再按当前主体生成 2–4 张同内容试稿。
5. 按“视觉方向推荐策略”从当前内容动态构造互斥方案。每个试稿使用不同的内容载体、视觉骨架、信息组织或证据形式；只有适配任务时才可引用“有限整套风格参考”。
6. 保持内容、比例、主体和关键信息一致，让用户只比较视觉方向；不得同时改变文案、卖点、人物身份或产品外观。

视觉澄清试稿和已有结果的纠偏试稿都可直接生成，作为“多版本任务需先生成确认”的特例。只要非视觉信息已经充分，生成前不调用 `interaction.ask` 做风格澄清或生成确认。

### 试稿必须拉开差异

2–4 个试稿不能只是换颜色、换滤镜或轻微调整装饰。任意两张之间至少改变以下三项：

- 主视觉骨架：居中英雄、对角线动势、非对称编辑网格、主图卫星、满版场景或大留白。
- 色彩与光线：明暗、冷暖、饱和度、主辅色关系、硬光或柔光。
- 媒介与材质：商业摄影、扁平插画、拼贴、纸艺、纸张、金属、玻璃、水彩或线描。
- 文字与版式：标题尺度、字体气质、文字容器、对齐方式和阅读动线。
- 氛围与叙事：专业克制、浪漫柔和、街头真实、高能潮流、安静怪诞或传统节庆。

不要保留用户已经否定的主风格，只做局部修补；除非用户明确说主体或构图满意，只需调整某一个维度。

### 试稿后用普通文本选择视觉锚点

展示 2–4 张试稿后，不调用 `interaction.ask`。在同一条普通文本中按图片顺序简短列出编号和可见差异，并提示用户直接回复图片编号或“都不合适”。该规则同时适用于初次视觉澄清和负向改稿。

- 每个编号必须对应一张已展示图片，只写图片编号和 1 句可见差异，不再讲抽象理论。
- 文本末尾允许写“直接回复 1 / 2 / 3 / 4，或回复‘都不合适’”；不得再附带问卷或结构化选项工具。
- 不同时询问配色、字体、构图、材质等二级问题，也不要求用户解释选择理由。
- 用户回复编号、指向某张图片或用自然语言明确选择后，直接锁定，不再调用任何确认工具。

用户选中后，将该试稿的 CDN URL 记录为新的 `visual-anchor`。后续整套图片统一以该锚点调用 `image_edit` 延展，不再询问同一风格问题。

若用户选择“都不合适，继续探索”或再次直接反馈“不好看”：

1. 不先追加问卷；根据已否定方向排除重复风格，直接再生成 2–4 张差异更大的新试稿。
2. 用户给出任何具体反馈时直接写入新试稿，例如“太花”转为更克制留白，“太冷”转为暖调自然光，“太像模板”转为真实场景或手作肌理。
3. 新试稿展示后仍只用普通文本列出编号并等待选择；不得为视觉锚点选择调用 `interaction.ask`。

### 用户已明确新风格时

如果用户已经给出可执行的新方向，例如“改成黑白硬光、留白多、杂志排版”，不要再做风格澄清：

- 只要求修改当前图时，直接生成 1 张改稿。
- 明确要求多方向对比时，再生成 2–4 张围绕该方向的差异化试稿。
- 不得为了套用本流程而强行扩展数量。

## `interaction.ask` 编写规范

宿主协议允许每次提交 1–4 个问题。本策略不再规定默认问题数量；先完成信息覆盖盘点，再在单次协议上限内提交所有当前已知、会真实改变图片结果或成品可用性的非视觉问题。不得为了少问而遗漏高价值信息，也不得为了占满问题位加入无关问题。

1. 核心事实与必需素材。
2. 图片内容形态：文字主导、文字 + 插画、图片 + 少量文字或纯画面。
3. 内容组织：单主体、主体 + 场景、多元素信息编排或连续分镜 / 分页。
4. 数量、比例、分辨率和导出规格。

### 信息覆盖盘点

调用 `interaction.ask` 前逐项检查以下维度，只询问仍未明确且会影响当前交付的内容：

1. **目的与场景**：最终用途、发布渠道、目标受众、阅读环境和希望用户完成的动作。
2. **准确内容**：标题、正文、品牌或产品名、时间地点、价格、数据、卖点、联系方式、行动入口及其来源。
3. **核心素材**：edit target、人物或产品参考、Logo、品牌资产、必须保持项、允许修改项和各素材角色。
4. **产物结构**：文字 / 图片 / 插画的内容形态、单图或多图、页面顺序、信息递进、每张图职责。
5. **交付范围**：数量、版本差异、比例、分辨率、导出格式、平台适配和是否需要分层。
6. **连续性要求**：人物、产品、角色、品牌、场景、画幅和跨页信息是否需要保持一致。

盘点完成后按“事实与核心素材 > 产物结构与内容组织 > 数量和逐项差异 > 使用场景与交付规格”的顺序占用问题位。多个紧密相关、必须一起提供才可执行的事实，可以在一个自由输入题中作为同一信息包列出，例如活动基本信息包含活动名、日期、地点和报名方式；不得把不相关决策强行塞进同一个问题。

普通澄清不得询问纯审美层面的风格、构图、配色、材质、光线、氛围或整体视觉偏好；这些决策按“视觉试稿澄清与风格改稿”处理。媒介或内容载体如果会改变素材需求、事实证据、产物路由、生成路径或交付结构，必须作为非视觉问题澄清。若用户已经明确全部非视觉信息，不调用 `interaction.ask` 凑问题。纯生成确认属于单决策工具调用，只包含 1 个问题。视觉试稿后的锚点选择不适用本节，必须使用普通文本。

### 入参字段协议

只使用以下已定义字段，不得把 `display_option` 写成 `options`、`choices` 或其他近义字段：

- 顶层对象必填 `questions`，类型为数组，每次包含 1–4 个问题，并按界面展示顺序排列。
- 每个问题必填 `question_id`、`header`、`display_message`。
- `question_id` 使用小写字母、数字和下划线，必须以字母开头，同一次调用内唯一，最长 64 个字符。
- `header` 是简短分类标题，最长 12 个字符。
- `display_message` 是最终展示给用户的完整问题文案，直接说明该信息对执行路径、内容完整度或成品可用性的影响。
- `display_option` 是可选的候选项数组；使用时必须包含 2–4 项，不得添加“其他”。
- `display_option` 中每项必填 `option_id`、`label`、`description`。
- `option_id` 使用小写字母、数字和下划线，必须以字母开头，同一问题内唯一，最长 64 个字符。
- `label` 是按钮短文案，最长 40 个字符。
- `description` 说明选项含义、影响或适用场景，最长 200 个字符。
- `multi_select` 为可选布尔值；省略时按 `false` 处理，只有候选项确实可以组合时才设为 `true`。

### 选项与自由输入边界

- 产物类型、内容形态、素材角色、数量结构、画幅、是否生成或是否继续等决策题，必须使用 `display_option` 提供 2–4 个互斥、可执行、结果导向的候选项。
- 品牌名、日期、准确文案、数据、联系方式、地点等无法预设的事实题，可以省略 `display_option`，让用户自由输入；这是协议允许的输入方式，不得为制造按钮而猜测事实。
- 同一个问题若可通过候选路径解决，也可使用 `display_option` 描述真实处理路径；但不能虚构事实答案，也不能提供会导致空白或不可用成品的假选项。
- 已知答案不得再次成为候选项；不可用、互相重叠或结果相同的候选项不得用来凑数。

### 最小合法结构示例

决策题使用 `display_option`：

```json
{
  "questions": [
    {
      "question_id": "output_structure",
      "header": "内容结构",
      "display_message": "成品结构会改变图片数量和每张图的职责，请选择本次交付方式。",
      "display_option": [
        {
          "option_id": "single_key_visual",
          "label": "单张主视觉",
          "description": "交付 1 张核心画面，集中表达一个主题。"
        },
        {
          "option_id": "four_image_set",
          "label": "四张基础套图",
          "description": "交付 1 张封面和 3 张分项内容图。"
        }
      ],
      "multi_select": false
    }
  ]
}
```

事实自由输入题可以省略 `display_option` 和 `multi_select`：

```json
{
  "questions": [
    {
      "question_id": "event_name",
      "header": "活动名称",
      "display_message": "画面必须使用真实活动名称，请填写需要展示的准确文案。"
    }
  ]
}
```

示例只说明字段结构，不是固定问题模板；实际调用仍须根据当前阻塞项改写。

### 常见问题的选项生成方式

根据当前任务改写，选项必须描述选择后的成品差异：

- **图片内容形态**：从“文字主导”“文字 + 插画”“图片 + 少量文字”“纯画面”中选择 2–4 个真正可用的选项。
- **内容组织**：从“单主体聚焦”“主体 + 场景叙事”“多元素信息编排”“连续分镜 / 分页”中选择 2–4 个与任务匹配的选项。
- **素材角色**：根据上传内容提供“作为编辑对象”“保持主体并换环境”“仅参考构图 / 配色”“作为辅助素材”等互斥处理方式；不要假设不存在的素材。
- **数量与结构**：每个选项同时写张数和逐张职责，例如“1 张主视觉”“4 张：封面 + 3 张分项”“6 张：封面 + 场景 + 细节 + 对比”。
- **画幅与交付**：只提供目标平台真实可用的比例，并说明其版面结果，例如“竖版：适合手机阅读”“横版：适合大屏或网页首屏”“方图：适合信息流卡片”。
- **是否生成**：使用“按以上参数生成”和“暂不生成”两个明确结果选项。

这些是选项构造方式，不是每次都要询问的固定问卷。只选择当前未明确，且会影响执行、内容完整度、成品可用性或明显返工成本的问题。

每个问题必须满足：

- 一个问题只解决一个决策。
- 决策题使用 `display_option` 提供 2–4 个互斥、可执行、结果导向的可点选候选项；事实自由输入题可以省略该字段。
- 不得把纯审美层面的风格、构图、配色、材质、光线、氛围或整体视觉方向写入 `interaction.ask`；需要用户选择时必须先生成视觉试稿，再使用普通文本编号。会改变素材需求、事实证据、产物路由、生成路径或交付结构的媒介与内容载体不属于纯审美，必须使用 `interaction.ask`。
- 只有候选项确实可以组合时才将 `multi_select` 设为 `true`；内容形态、比例和是否生成通常省略该字段或设为 `false`。
- 调用前验证字符长度、ID 格式、必填字段和候选项数量；不符合时先重写参数，不得以普通文本代替。

需要澄清时，除生成确认所需的最终参数展示外，不额外输出长篇复述、方案解释、免责声明或“请确认”。

## 单次澄清后直接执行

用户回答 `interaction.ask` 后，该答案同时视为：

- 对问题中数量、产物结构、规格、素材范围和事实内容的锁定。
- 对按照这些已确认参数进入当前执行阶段的授权。

固定处理顺序：

1. 将答案合并进已有上下文和内部计划。
2. 重新计算图片数量、角色矩阵、比例、工具路径和核心资产依赖。
3. 对用户已回答的内容不复述成问题，不再调用 `interaction.ask` 做二次确认。
4. 可以用一句陈述性进度说明概括即将执行的内容，但不得包含问句、选项或“请确认”。
5. 返回主 `SKILL.md` 的串行读取流程；此时才读取且只读取一个模型改写策略 reference，组装 prompt 后直接调用图片工具执行。

以下情况都不得再次调用 `interaction.ask`：

- 用户从已有选项中作出了明确选择。
- 用户用自由输入补充了可执行答案。
- 用户的答案改变了数量、比例、产物结构或素材范围，但改变后的要求本身已经明确。
- 当前任务达到系列图、批量图、多版本或高分辨率复杂处理门槛；只要此前普通澄清已经回答，就跳过独立生成确认。
- 用户在普通文本回复中指定了一张视觉试稿；立即记录为 `visual-anchor` 并继续，不再确认风格。

首次澄清后仍有非关键缺失时，使用安全默认值或缩减不受支持的可选内容，不开启第二轮问卷。若用户答案引入了此前无法预见、且不解决就会编造事实、混淆身份或引用错误核心资产的新硬阻塞，停止依赖该项的步骤并简短报告；优先等待用户主动补充，不连续调用 `interaction.ask`。只有用户明确要求继续解决该新阻塞时，才可开启新的澄清阶段。

## 生成确认

以下任务达到生成确认门槛：

- 系列图、批量图、叙事多图、多版本方向。
- 高分辨率复杂处理或明显高成本批处理。
- 需要先生成核心资产，再依赖它生成其他资产。
- 需要在文生图与图生图之间切换的多阶段任务。
- 多比例、多平台、多物料或完整方案、系统、全案。

单张普通图片信息充分时直接执行，不做生成确认。

生成确认只适用于：当前执行阶段没有进行过普通澄清，但信息本身已经充分，且任务达到上述确认门槛。只要用户已经回答过普通澄清，该回答即视为执行授权，必须跳过本节确认；随后返回主流程读取模型改写策略并生成。

确认流程固定为：

1. 用普通文本展示已锁定的最终参数，只陈述：命中的产物 ref、核心资产顺序、每张图目的、数量、逐项差异、比例 / 分辨率、素材范围和生成批次。该文本不得包含问句或选项。
2. 单独调用一次 `interaction.ask`，只询问是否按以上参数生成。
3. 调用后等待用户回答，不追加问题，不继续生成。

不得在普通澄清之后紧接着再做生成确认。只有未发生普通澄清时才使用上述确认流程；确认后不得静默改变数量、规格、方向或素材范围。

## 批量生成与阶段反馈

- 一次最多生成 10 张；超过 10 张时，先按用户顺序或代表性规划批次，并在生成确认参数中写明首批范围。
- 首批完成后展示结果。如后续仍有待生成图片，是否继续下一批、文字事实、人物身份和素材范围等非视觉决策使用 `interaction.ask`；风格、构图和配色反馈不得放进该工具。
- 用户需要选择或改变视觉方向时，立即进入“视觉试稿澄清与风格改稿”流程，先生成 2–4 张试稿，再用普通文本让用户回复编号选择视觉锚点。
- 用户提出明确修改意见时直接修改；只有确实需要用户作新决策时才调用 `interaction.ask`，不得重复询问已给出的反馈。
- 用户确认继续后，可按计划分批完成，每批不超过 10 张。
- 后续若需要改变已锁定视觉方向，直接生成新试稿并用普通文本选锚点；若改变数量、规格或素材范围，则对这些非视觉变化使用 `interaction.ask`。

## 工具失败与用户回答后的处理

- 用户回答普通澄清后，将返回值并入已有上下文，重新计算参数，随后读取模型改写策略并执行；不要重复询问、再次要求同类确认或追加生成确认。
- 回答改变数量、规格、产物结构或素材范围时，只需更新最终参数并执行。不得因为参数发生变化再次调用 `interaction.ask`。
- 用户在生成确认中选择生成：直接执行，不重复确认。
- 用户选择暂不生成：停止生成，不擅自执行替代方案。
- 用户回答仍未解决硬阻塞时，停止依赖该项的步骤并报告具体阻塞；不要连续调用 `interaction.ask`。用户主动要求继续解决该阻塞时，才进入新的澄清阶段。
- `interaction.ask` 不可用或失败：停止依赖答案的步骤，报告工具不可用；不输出替代问题。
- 视觉试稿生成工具不可用或失败：报告无法完成视觉澄清，不得退回 `interaction.ask` 询问风格、构图或配色。

## 禁止事项

- 为形式完整而询问与执行无关的信息。
- 把完整需求表一次性丢给用户。
- 决策题调用 `interaction.ask` 时遗漏 `display_option`、候选项不是 2–4 个、缺少 `option_id` / `label` / `description`，或错误使用 `options` / `choices` 字段。
- 重复询问已经回答的内容。
- 用户回答普通澄清后，又追加一次生成确认、参数确认或同义问题。
- 用户已经反馈“不好看”或要求换风格后，连续调用 `interaction.ask` 追问审美偏好，而不先提供可比较的视觉试稿。
- 展示 2–4 张审美纠偏试稿后，仍调用 `interaction.ask` 让用户选择视觉锚点。
- 在初次视觉澄清时，用 `interaction.ask` 询问纯审美层面的风格、构图、配色、材质、光线、氛围或整体视觉方向，而不是先生成 2–4 张实际试稿；但会改变素材、路由或交付结构的媒介问题仍必须调用该工具。
- 把同一基准图的轻微换色、换滤镜或装饰位移当作 2–4 个风格方案。
- 用抽象形容词作为非视觉选项，或把抽象形容词原样写入视觉试稿 prompt。
- 擅自编造事实或用占位事实进入最终生成。
- 在普通澄清中夹带“是否开始生成”。
- 产物类型未确定就先做视觉提案、排版或生成。
- 判断需要澄清后用普通文本或 Markdown 选项绕过 `interaction.ask`。
- 在等待工具回答时继续生成。
- 让产物 reference、自定义张数策略或默认值覆盖本协议的硬门禁。
