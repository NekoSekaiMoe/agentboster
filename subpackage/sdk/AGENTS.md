# AGENTS.md — subpackage/sdk/

Cross-tier public SDK for the AgentBoster platform. Today the SDK only
re-exports the **CLI runtime** surface (`@agentboster-cli/core`); the
long-term scope covers five surfaces — CLI runtime, Web HTTP API,
Workflow DevKit, Desktop IPC/bridge, and the agentd tool protocol.
See `docs/ARCHITECTURE.md` for the tier model and surface maturity.

## Layout

- `src/index.ts` — explicit re-export list (CLI surface today, ~350
  names mirroring the runtime). Regenerated by
  `scripts/regen-exports.py`. Do NOT hand-edit the CLI export block —
  it's generated. Other surfaces (Web/Workflow/Desktop/Agentd) will
  land here as typed modules under their own subdirectories.
- `src/compat.ts` — cross-runtime-version helpers (`resolveModelApiKey`).
- `vendor/core.d.ts` — minimal CLI type stub (all types as `any`) so the
  SDK type-checks without the cli workspace. Regenerated by
  `scripts/regen-stubs.py`.
- `scripts/regen-stubs.py` + `scripts/regen-exports.py` — keep
  `vendor/core.d.ts` and `src/index.ts` in sync with the **CLI** runtime.
  Each new surface will get its own regen script that pulls from that
  surface's source of truth.
- `docs/` — canonical docs:
  `PACKAGES.md`, `CAPABILITY_MODEL.md`, `PACKAGE_CAPABILITY_TEMPLATE.md`,
  `ARCHITECTURE.md`. The Desktop-specific docs (ICONS, PERMISSIONS,
  THEMES_DESKTOP_MAPPING, RELEASES) stayed in `desktop/docs/`.
- `examples/` — five reference CLI extensions, each covering a distinct
  pattern. Type-checked by `examples/tsconfig.json` (less strict than
  the SDK itself — examples are reference code, not production code).
- `README.md` — author-facing intro covering all five surfaces and
  their maturity (ready vs roadmap).

## When the CLI runtime's public surface changes

Whenever `cli/packages/coding-agent/src/index.ts` adds or removes an
export:

```bash
cd subpackage/sdk
yarn regen-stubs   # or: python3 scripts/regen-stubs.py && python3 scripts/regen-exports.py
yarn check:lint
```

This regenerates both `vendor/core.d.ts` (the stub used for standalone
type-check) and `src/index.ts`'s CLI export block. Commit both.

Other surfaces do not have a regen path yet — they are sourced by hand
from each tier's source of truth until a per-surface script is added.

## Module

Standalone npm package (`@agentboster/sdk`). NOT part of the
`cli/` Yarn workspace — install it independently. Ships as TypeScript
source (the CLI runtime compiles extensions via jiti), so there is no
build step.

## Conventions

- **Re-exports, not copies.** A type belongs in the SDK only if it is
  already public in its source tier. Don't duplicate type definitions
  here; if a type is missing, add it to the tier's source of truth
  first (CLI: `core/extensions/types.ts`; Web/Workflow/Desktop/Agentd:
  their respective public types), then re-export.
- **One surface at a time.** When adding a new surface, land it under
  its own `src/<surface>/` subdirectory with its own stub and regen
  path. Do not mix surfaces in the same file — it breaks independent
  regen.
- **Manifest namespace.** Document both `agentboster` (current) and
  `pi` (legacy) in examples. The runtime accepts both; new docs prefer
  `agentboster`.
- **Tier-local implementations win.** The SDK is a curated view, not a
  fork. Each tier's internals stay in that tier; only the public
  contract is mirrored here.
- **Helpers go in `src/compat.ts`.** Cross-version helpers (shims for
  API changes between runtime versions) live there. Don't inline them
  in examples.

## Adding new public types

For the **CLI runtime** (ready):

1. Add the type to `cli/packages/coding-agent/src/core/extensions/types.ts`
   (the source of truth).
2. Re-export from `cli/packages/coding-agent/src/core/extensions/index.ts`
   and (if it's truly public) from `coding-agent/src/index.ts`.
3. Run `yarn regen-stubs` to refresh `vendor/core.d.ts` and `src/index.ts`.
4. If it has a cross-version compatibility story, add a helper in
   `sdk/src/compat.ts`.
5. Document in `sdk/docs/PACKAGE_CAPABILITY_TEMPLATE.md` if it's part
   of the recommended authoring flow.

For the **roadmap surfaces** (Web/Workflow/Desktop/Agentd): until each
surface gets a regen script, add the type to the tier's source of truth
first, then hand-port the public shape into the SDK under
`src/<surface>/`. Mark the export with a comment pointing back to the
source file so future regen tooling can find it.

## Docs sync

When `desktop/docs/PACKAGES.md` or related docs change, update the copy
in `sdk/docs/` too. The Desktop copies are kept as the "applied" view
(desktop-specific examples inline); the SDK copies are the canonical
generic version. Prefer editing the SDK version and let Desktop follow.

When the platform-tier boundaries change (new surface, new auth
pattern, new event schema), update `docs/ARCHITECTURE.md` and the
maturity table in `README.md` together — they describe the same model.
